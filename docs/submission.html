1. What it does

Post Studio is a local web app that helps an engineer publish on LinkedIn consistently without giving up control. Claude drafts and improves posts in the author's own voice, a humanizer removes the "written by AI" fingerprint, a governance gate blocks anything confidential, and nothing is published until a named person approves it. Published posts are tracked with real, hand-entered readings, never estimated.

The problem

Engineers ship a lot of work that nobody outside the team sees. Writing always comes last. Generic AI tools make posting faster but produce text that reads as machine-written, and they can leak client names or internal numbers.

The solution, in one line

Idea → Claude draft → Humanizer → Score + compliance gate → Human approval → Queue → LinkedIn → Performance tracking.

4. How a post flows through the system

  1. Draft. The author types an idea and the facts Claude may use. /api/draft sends it to Claude with the li-post skill and the voice profile as instructions, and gets back structured output (hooks, draft, placeholders) validated with zod.
  2. Humanize and score. /api/check runs humanize.py and detect.py from the li-human skill and returns the cleaned text, a diff and the human score.
  3. Gate. gate.ts combines the score with the compliance check (off-limits.txt), placeholder check, length limit and approver name. Any hard failure blocks approval. This runs on the server, not only in the browser.
  4. Approve. A named approver confirms. The approval is written to an append-only log. The post is published now, scheduled, or added to the queue in the next free weekly slot.
  5. Publish. linkedin.ts calls LinkedIn's Posts API with the stored OAuth token (and the Images API for an attached image). For scheduled posts, the worker does this when the slot arrives, after re-checking the off-limits list.
  6. Track. The author adds readings (impressions, reactions, comments, reposts, plus a screenshot) at 1h, 3h, 6h, 12h, 24h, 48h, 72h and 7 days. Charts, hourly/daily gains and comparisons are computed only from these real readings.

LinkedIn's w_member_social permission allows posting but not reading post analytics. Reading analytics through the API needs r_member_postAnalytics, which LinkedIn grants only to approved Community Management API apps, so readings are entered by hand from LinkedIn's own numbers. Post Studio does not scrape LinkedIn.

6. Safety and governance by design

Human in the loop. Every post needs a named approver and an explicit confirmation. Live posting is off unless POST_STUDIO_LIVE=1; otherwise everything is a logged dry run.
No leaks. The off-limits list blocks client names, internal metrics and NDA terms at approval and again right before posting.
No invented facts. Claude is instructed to use only facts the author supplied. Gaps become placeholders that block approval until filled.
Secrets stay local. API keys and tokens live in gitignored files with owner-only permissions and are never sent to the browser or committed.
No automation of people. It never comments, messages, follows or scrapes. Engagement lists are suggestions the author acts on manually.
Real numbers only. Analytics show only readings the author entered, each with its screenshot as evidence.

7. Setup, step by step

  1. Prerequisites: Node.js 20+, Python 3, the li-human and li-post skills in ~/.claude/skills, rsvg-convert, and either an Anthropic API key or the Claude Code CLI.
  2. Install: cd post-studio && npm install
  3. Configure: create post-studio/.env.local with LINKEDIN_CLIENT_ID, LINKEDIN_CLIENT_SECRET, ANTHROPIC_API_KEY (optional), LI_VERSION and POST_STUDIO_LIVE=0.
  4. LinkedIn app: at developer.linkedin.com create an app linked to a Company Page, add the products Sign In with LinkedIn using OpenID Connect and Share on LinkedIn, and add the redirect URL http://localhost:3009/api/linkedin/callback.
  5. Run: npm run dev and open http://localhost:3009. In a second terminal, npm run worker for scheduled posts.
  6. Connect: Settings → Connect LinkedIn, then set the approver name, posting slots, hashtag count, link placement and off-limits list.
  7. Go live: set POST_STUDIO_LIVE=1 and restart the app and the worker.

8. Result so far

The workflow was used end to end to publish a real post to LinkedIn on 19 November 2026 (approved through the gate, published through the official API). Readings entered from LinkedIn: 336 impressions at about 2 hours, 487 at about 17 hours and 607 impressions with 6 reactions at about 2 days.
